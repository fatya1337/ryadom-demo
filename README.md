# Рядом — единый кабинет психотерапевта

https://fatya1337.github.io/ryadom-demo/

Новые функции встроены в первоначальный дизайн. Главная /, прежняя ссылка
/showcase/ и /live/ открывают один компонент app/live/workspace.tsx. Отдельных
старой и расширенной версий больше нет. /patient/ — личный кабинет пациента.

Реестр с поиском/фильтрами, история и свои даты, настроение/сон/энергия,
поиск в записях, личная заметка, подготовка к встрече, сводка и JSON.
Учебный код DEMO-048 добавляет пустой дневник. «Учебные данные» внизу:
отзыв доступа и сброс. Это симуляции; настоящего приглашения код не создаёт.

Дневник Александры (Р-014) и её разрешение общие для кабинетов на этом сайте.
Откройте их в двух вкладках ОДНОГО браузера/профиля: сохранение пациентом сразу
обновляет историю, график и реестр специалиста. Новый код из «Мой специалист»
принимается в «Ввести код пациента». Отзыв убирает дневник у специалиста.
В показе используйте почту specialist@example.test; это вымышленный адрес.

Связь работает через BroadcastChannel, без API/базы/авторизации. Между устройствами,
разными браузерами, профилями и обычным/инкогнито окнами связи нет. Общий дневник
и доступ находятся только в памяти открытых вкладок; новая вкладка получает их
от существующей. Закрытие всех вкладок или общий сброс возвращает пример.
Заметки/подготовка специалиста и план пациента остаются локальными до reload.
При одновременной правке одного дня до получения событий действует детерминированное
разрешение конфликта; это учебная модель, не серверные транзакции.
Не переносить demo-link/demo-client в рабочие API-клиенты команды. Реальные медицинские данные вводить нельзя.
Личные заметки и подготовка не входят в экспорт дневника.
Серверная версия — barmood-team/platform-doctor (feat/shared-backend), пациент —
platform-biplyar (feat/patient-live), общий PostgreSQL / Prisma / Better Auth.

## Сборка Pages
STATIC_EXPORT=1 NEXT_PUBLIC_BASE_PATH=/ryadom-demo npm run build

node_modules и сборки. Отчёт о разработке передаётся отдельно, не вместо сайта.
